**src/lib/validators.ts** — Replace line 19:

```typescript
// Before:
guestPhone: z.string().min(1, 'Phone number is required'),

// After:
guestPhone: z
  .string()
  .min(1, 'Phone number is required')
  .regex(/^\+?[0-9\s\-]{7,20}$/, 'Enter a valid phone number (digits, spaces, or hyphens only)'),
```

The regex `/^\+?[0-9\s\-]{7,20}$/` accepts:
- Optional leading `+` (international prefix)
- Then 7–20 characters that are digits, spaces, or hyphens
- Covers SG local (8 digits), SG with country code (+65 XXXX XXXX = 12 chars with spaces), and common international formats

No changes needed to `src/app/(guest)/book/[eventId]/actions.ts` — the existing `guestPhone: 'phone'` map entry already routes a Zod regex error on `guestPhone` to the `phone` field in `fieldErrors`.

**src/app/(guest)/book/[eventId]/BookingForm.tsx** — Add a module-level constant and replace the phone presence check in `validateStep`:

Add at module level (after the imports, before `blankGuest`):
```typescript
// Must mirror the regex in src/lib/validators.ts guestPhone
const PHONE_RE = /^\+?[0-9\s\-]{7,20}$/
```

In `validateStep`, replace:
```typescript
// Before:
if (!state.contact.phone.trim()) errors.phone = 'Required'

// After:
if (!state.contact.phone.trim()) {
  errors.phone = 'Required'
} else if (!PHONE_RE.test(state.contact.phone)) {
  errors.phone = 'Enter a valid phone number (digits, spaces, or hyphens only)'
}
```

This ensures the client rejects bad format before the user attempts to reach Step 4, without waiting for a server round-trip.

```tsx
// Before:

  id="contact_phone"
  label="Phone number"
  type="tel"
  inputMode="tel"
  pattern="^\+?[0-9\s\-]{7,20}$"

  value={contact.phone}
  onChange={handleChange('phone')}
  error={errors.phone}
  placeholder="+65"
/>
```

`inputMode="tel"` opens the numeric dialler keyboard on iOS/Android. `pattern` is a browser-side hint only — Zod in `validators.ts` remains the authoritative gate. Do NOT add any `onChange` sanitisation that strips characters as the user types; the error message on Next-click is sufficient UX.
