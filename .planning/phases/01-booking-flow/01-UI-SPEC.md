# Phase 1 — UI Design Contract

> Visual and interaction contract for the 4-step booking flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (custom UI atoms in `src/components/ui/`) |
| Icon library | lucide-react |
| Font | Oswald (headings), Geist Sans (body) |

Existing atoms reused in this phase: `Button`, `Input`, `Select`, `Badge`, `Modal`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, `gap-1` |
| sm | 8px | Compact element spacing, form field gap within a row |
| md | 16px | Default element spacing, form field vertical gap, card padding inline |
| lg | 24px | Section padding, card padding block, step content padding |
| xl | 32px | Step-to-step vertical gap, page horizontal padding (mobile) |
| 2xl | 48px | Major section breaks (hero to form) |
| 3xl | 64px | Not used in this phase |

Exceptions: Touch targets for stepper dots and increment/decrement buttons must be minimum 44x44px (accessibility).

## Typography

| Role | Size | Weight | Line Height | Font | Tailwind Class Pattern |
|------|------|--------|-------------|------|----------------------|
| Body | 14px | 400 (regular) | 1.5 | Geist Sans | `text-sm` |
| Label | 14px | 400 (regular) | 1.4 | Geist Sans | `text-sm text-burgundy-600` |
| Heading | 20px | 700 (bold) | 1.2 | Oswald | `font-heading text-xl font-bold uppercase tracking-wide` |
| Display | 28px | 700 (bold) | 1.2 | Oswald | `font-heading text-2xl sm:text-3xl font-bold uppercase tracking-wide` |

Two weights only: 400 (regular) for all body and label text, 700 (bold) for all heading and display text. Labels are visually distinguished from body text through color (`text-burgundy-600`) rather than weight. Display is used only for the event title in the booking page header. Heading is used for step titles. Body and Label cover all form content.

## Component Inventory

### Step Indicator (new)

A horizontal step progress bar at the top of the form.

- 4 dots connected by a track line
- Active step: `bg-burgundy-700` dot, `text-burgundy-900` label
- Completed step: `bg-burgundy-700` dot with checkmark icon (16px)
- Upcoming step: `bg-cream-300` dot, `text-burgundy-400` label
- Track between dots: `bg-cream-300`, completed segments `bg-burgundy-700`
- Dot size: 32px diameter (meets 44px touch target with padding)
- Step labels below dots: "Party", "Dietary", "Contact", "Review"
- Not clickable (linear progression only)

### Step 1: Party Size + Wine Pairing

| Element | Component | Notes |
|---------|-----------|-------|
| Seat availability | `Badge` (success/warning/default) | ISR 60s, shows "{N} seats remaining" or "Sold out" |
| Party size selector | `Select` | Options: 1-8 (or up to seats remaining, whichever is lower) |
| Wine pairing toggle | Checkbox (native `<input type="checkbox">`) | Only shown when `event.wine_pairing === true` |
| Wine pairing count | `Select` | Options: 1 through pax. Only visible when wine toggle is checked |
| Price summary | Static text block | Shows `{pax} x {price_per_seat} = {subtotal}` and wine line if applicable, then total in bold |

### Step 2: Allergy/Dietary Info

Renders one fieldset per guest (labeled "Guest 1", "Guest 2", etc.).

| Element | Component | Notes |
|---------|-----------|-------|
| Guest name | `Input` | Pre-filled with "Guest {N}", required |
| Allergies | Checkbox group (native) | Common allergens: Shellfish, Nuts, Dairy, Gluten, Eggs, Soy, Fish, Sesame |
| Other allergies | `Input` | Free text, shown always |
| Dietary restrictions | Checkbox group (native) | Options: Vegetarian, Vegan, Pescatarian, Halal, Kosher |
| Severity | `Select` | Options: Preference, Intolerance, Life-threatening. Default: "Preference" |
| Special requests | `<textarea>` | 3 rows, placeholder: "Any other requests for the chef..." |

Each fieldset has a cream-200 background card with 24px padding and 8px rounded corners.

### Step 3: Contact Details

| Element | Component | Notes |
|---------|-----------|-------|
| Full name | `Input` | type="text", required, autocomplete="name" |
| Email | `Input` | type="email", required, autocomplete="email" |
| Phone | `Input` | type="tel", required, autocomplete="tel", placeholder: "+65" |

All three fields stacked vertically with 16px gap.

### Step 4: Review + Confirm

Read-only summary of all previous steps. Grouped into sections:

| Section | Display |
|---------|---------|
| Event header | Event title, date, time, venue (pulled from server data, not form state) |
| Party details | "{pax} guests, {wine_count} wine pairings" |
| Guest details | Accordion-style list: guest name, allergies (as badges), severity badge, special requests |
| Contact | Name, email, phone |
| Price breakdown | Line items + bold total |

Each section separated by `border-cream-300` divider. Edit links (text button, `text-burgundy-700 underline`) next to each section heading to jump back to that step.

### Navigation Footer (per step)

Fixed to bottom of viewport (same position as event detail CTA bar).

| Element | Behavior |
|---------|----------|
| Back button | `Button variant="ghost"` with left arrow. Hidden on step 1. |
| Next / Confirm button | `Button variant="primary" size="lg"`. Label changes per step (see Copywriting). |
| Submitting state | Button shows "Reserving..." with `disabled` attribute. Spinner icon replaces arrow. |

Container: `bg-white border-t border-cream-300 shadow-lg`, same `max-w-3xl mx-auto` as page content.

### Success State (post-submission)

Full-page replacement (not a modal). Centered content:

- Checkmark circle icon: 64px, `text-sage-600`
- Heading: "Booking Confirmed"
- Booking reference: the returned UUID truncated to first 8 chars, monospace
- Summary: "{pax} seats at {event_title}"
- "Back to Events" link button

## Interaction Contracts

### Form State Management

- `useReducer` manages all form state (decided in STATE.md)
- State shape: `{ step, pax, winePairingCount, wineOptIn, guestDetails[], contact: { name, email, phone } }`
- Step transitions: dispatch `NEXT_STEP` / `PREV_STEP` actions
- Validation runs on `NEXT_STEP` dispatch; if invalid, errors populate and step does not advance

### Session Storage Persistence (BOOK-08)

- On every state change, serialize non-PII fields to `sessionStorage` key `booking:{eventId}`
- Persisted: `step`, `pax`, `winePairingCount`, `wineOptIn`, `guestDetails[]`
- NOT persisted: `contact.name`, `contact.email`, `contact.phone` (PII)
- On mount, restore from sessionStorage if key exists
- Clear sessionStorage on successful submission

### Seat Availability (BOOK-06)

- Event data fetched server-side (ISR 60s revalidation, already set on event detail page)
- `seatsLeft` passed as prop to client form component
- Party size `Select` max option = min(8, seatsLeft)
- If seatsLeft === 0 on page load, show sold-out state instead of form
- If `create_booking` RPC returns seat error, display inline error banner above navigation footer

### Double-Submit Prevention (BOOK-07)

- Track `isSubmitting` boolean in reducer state
- On `SUBMIT` dispatch: set `isSubmitting = true`, disable confirm button, change label to "Reserving..."
- On success: redirect to success view
- On error: set `isSubmitting = false`, display error, re-enable button

### Form Validation

| Field | Rule | Error Copy |
|-------|------|-----------|
| pax | required, 1-8, <= seatsLeft | "Select party size" / "Only {N} seats available" |
| guestDetails[].guest_name | required, non-empty | "Guest name is required" |
| contact.name | required, non-empty | "Full name is required" |
| contact.email | required, valid email regex | "Please enter a valid email address" |
| contact.phone | required, non-empty | "Phone number is required" |

Validation errors appear directly below the offending input using the existing `Input` error prop (red-600 text, 12px).

## Layout Contract

### Page Structure

```
/book/[eventId] (client component page)
  |-- Compact event header (burgundy-900 bg, event title + date + price)
  |-- Step indicator (4 dots + track)
  |-- Step content (scrollable area, cream-50 bg)
  |-- Fixed navigation footer (white bg, border-t)
```

### Dimensions

| Element | Value |
|---------|-------|
| Page max-width | `max-w-3xl` (768px) centered |
| Page horizontal padding | `px-4 sm:px-6 lg:px-8` |
| Form content vertical padding | 24px top, 96px bottom (clear fixed footer) |
| Fixed footer height | ~68px (py-3 + button height) |
| Card border radius | `rounded-lg` (8px) |
| Input border radius | `rounded-md` (6px) |
| Button border radius | `rounded-md` (6px) |

### Responsive Notes

- Single-column layout at all breakpoints (max-w-3xl is narrow enough)
- Mobile responsive polish is Phase 3; this phase targets desktop-first but uses the existing responsive padding pattern
- iOS Safari fixed-bottom CTA keyboard issue is a known concern (STATE.md) — addressed in Phase 3
