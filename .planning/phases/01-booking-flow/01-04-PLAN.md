**Reducer implementation:**

The `bookingReducer` must handle all action types. Key implementation details:

- `SET_PAX`: update `pax`, resize `guestDetails` array (trim or pad with blank entries), clamp `winePairingCount = Math.min(state.winePairingCount, newPax)`. Reset `errors`.
- `SET_WINE_OPT_IN`: update `wineOptIn`. If false, reset `winePairingCount` to 0.
- `SET_WINE_COUNT`: update `winePairingCount`.
- `SET_GUEST_DETAIL`: update `guestDetails[index][field]` immutably.
- `SET_CONTACT`: update `contact[field]`.
- `NEXT_STEP`: increment step (max 4). Clear `errors`.
- `PREV_STEP`: decrement step (min 1). Clear `errors`.
- `GO_TO_STEP`: set step directly. Clear `errors`.
- `SUBMIT`: set `isSubmitting: true`, clear `errors`.
- `SET_ERROR`: set `errors._form = action.error`, set `isSubmitting: false`.
- `SET_SUCCESS`: set `bookingId = action.bookingId`, set `isSubmitting: false`.
- `RESTORE`: merge `action.payload` into state (spread). Do NOT restore `isSubmitting` or `bookingId` from sessionStorage — those are transient.

**Full component structure:**

```typescript
'use client'

import { useReducer, useEffect, startTransition } from 'react'
import type { Database } from '@/types/database'
import StepIndicator from './StepIndicator'
import StepParty from './StepParty'
import StepDietary from './StepDietary'
import StepContact from './StepContact'
import StepReview from './StepReview'
import BookingSuccess from './BookingSuccess'
import { submitBooking } from './actions'

type Event = Database['public']['Tables']['events']['Row']

// --- Type exports (step components import from here in Plan 04+) ---
export type { GuestDetail, FormState, BookingAction }

// --- Reducer ---
function blankGuest(): GuestDetail { ... }
function bookingReducer(state: FormState, action: BookingAction): FormState { ... }

// --- Component ---
interface BookingFormProps {
  event: Event
  seatsLeft: number
}

export default function BookingForm({ event, seatsLeft }: BookingFormProps) {
  const SESSION_KEY = `booking:${event.id}`
  const [state, dispatch] = useReducer(bookingReducer, initialState)

  // Restore from sessionStorage on mount
  useEffect(() => {
    const saved = sessionStorage.getItem(SESSION_KEY)
    if (saved) {
      try {
        const parsed = JSON.parse(saved)
        dispatch({ type: 'RESTORE', payload: parsed })
      } catch {
        // corrupt storage — ignore
      }
    }
  }, [])  // eslint-disable-line react-hooks/exhaustive-deps

  // Save to sessionStorage on state change (exclude PII contact fields)
  useEffect(() => {
    if (state.bookingId) {
      sessionStorage.removeItem(SESSION_KEY)
      return
    }
    const { contact: _contact, ...nonPii } = state
    sessionStorage.setItem(SESSION_KEY, JSON.stringify(nonPii))
  }, [state])  // eslint-disable-line react-hooks/exhaustive-deps

  function handleConfirm() {
    dispatch({ type: 'SUBMIT' })
    startTransition(async () => {
      const result = await submitBooking({
        eventId: event.id,
        guestName: state.contact.name,
        guestEmail: state.contact.email,
        guestPhone: state.contact.phone,
        pax: state.pax,
        winePairingCount: state.winePairingCount,
        guestDetails: state.guestDetails,
      })
      if ('error' in result) {
        dispatch({ type: 'SET_ERROR', error: result.error })
      } else {
        dispatch({ type: 'SET_SUCCESS', bookingId: result.bookingId })
      }
    })
  }

  // Success state — full page replacement
  if (state.bookingId) {
    return <BookingSuccess bookingId={state.bookingId} pax={state.pax} event={event} />
  }

  return (
    <div className="min-h-screen bg-cream-50">
      <div className="max-w-lg mx-auto px-4 py-8">
        <StepIndicator current={state.step} />

        <div className="mt-8">
          {state.step === 1 && (
            <StepParty event={event} seatsLeft={seatsLeft} state={state} dispatch={dispatch} />
          )}
          {state.step === 2 && (
            <StepDietary state={state} dispatch={dispatch} />
          )}
          {state.step === 3 && (
            <StepContact contact={state.contact} errors={state.errors} dispatch={dispatch} />
          )}
          {state.step === 4 && (
            <StepReview event={event} state={state} dispatch={dispatch} onConfirm={handleConfirm} />
          )}
        </div>

        {/* Step navigation — Back / Next */}
        <div className="mt-8 flex justify-between">
          {state.step > 1 && (
            <button
              type="button"
              onClick={() => dispatch({ type: 'PREV_STEP' })}
              className="text-sm text-burgundy-700 underline"
            >
              Back
            </button>
          )}
          {state.step < 4 && (
            <button
              type="button"
              onClick={() => dispatch({ type: 'NEXT_STEP' })}
              className="ml-auto text-sm font-medium bg-burgundy-700 text-white px-6 py-2 rounded-md hover:bg-burgundy-800 transition-colors"
            >
              Next
            </button>
          )}
        </div>
      </div>
    </div>
  )
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sessionStorage → RESTORE action | Data read from sessionStorage is parsed and dispatched — could be manipulated by user or extensions |
| handleConfirm → submitBooking | Payload assembled from reducer state; all fields flow through server-side Zod validation before RPC |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | RESTORE payload from sessionStorage | accept | sessionStorage is same-origin; malicious data would only corrupt the user's own form state. Server action re-validates all fields before RPC call. |
| T-04-02 | Tampering | Double-submit via rapid clicks | mitigate | `dispatch({ type: 'SUBMIT' })` sets `isSubmitting: true` synchronously before `startTransition`; button `disabled={state.isSubmitting}` prevents second click. DB `FOR UPDATE` lock is the safety net. |
| T-04-03 | Information Disclosure | Contact PII in sessionStorage | mitigate | `const { contact: _contact, ...nonPii } = state` excludes contact object from the serialized payload written to sessionStorage. |
| T-04-04 | Information Disclosure | bookingId in sessionStorage on restore | mitigate | RESTORE action sets `bookingId: null` — stored sessions never carry a success state back into the form. |
</threat_model>
